## 대상 프로젝트 확인

`package.json`에 `react` 의존성이 없으면 이 스킬을 실행하지 않는다.

---

## 실행 절차

### Step 1. 프로젝트 설정 파악

`write-test`와 동일하게 `project-config.md`를 먼저 찾는다.
없으면 `package.json`, `vitest.config.*` 등을 읽어 파악한다.

---

### Step 2. 테스트 파일 읽기

검토 대상 파일을 읽는다. 범위가 지정되지 않은 경우 사용자에게 확인한다.

---

### Step 3. 검수

`review-checklist.md`의 검수 순서대로 평가한다.
각 관점에서 참조 문서의 ❌ 패턴 및 원칙 위반을 확인한다.

---

### Step 4. 결과 출력

**문제가 없는 경우**: 한 줄로 "문제 없음" 과 근거를 밝힌다.

**문제가 있는 경우**: 아래 포맷으로 출력한다.

```
파일경로:L줄번호: 문제. 수정 방향.
```

심각도 prefix (혼재 시):
- `🔴` 테스트 신뢰도를 크게 낮추는 패턴 (잘못된 모킹, 구현 기반 테스트 등)
- `🟡` 유지보수 비용을 높이는 패턴 (waitFor 오용, 불필요한 모킹 등)
- `🔵` 가독성/관례 개선 (디스크립션, 쿼리 우선순위 등)

**추가 규칙**:
- 한 줄로 작성한다. 문제와 수정 방향이 명확하면 이유는 생략한다.
- 수정 코드가 짧고 명확한 경우 인라인으로 제시한다.
- 같은 패턴이 여러 곳에 반복되면 첫 번째만 표시하고 "동일 패턴 N건 추가"로 요약한다.
- 테스트 유형 자체가 잘못된 경우 `test-selection.md` 기준으로 어떤 유형이 더 적합한지 제안한다.
