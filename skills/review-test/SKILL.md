## 대상 프로젝트 확인

`package.json`에 `react` 의존성이 없으면 이 스킬을 실행하지 않는다.

---

## 실행 절차

### Step 1. 프로젝트 설정 파악

`project-config.md`를 먼저 찾는다.
없으면 `package.json`, `vitest.config.*` 등을 읽어 파악한다.

---

### Step 2. 검토 대상 파일 선정

**범위가 명시된 경우**: 해당 파일 또는 폴더를 대상으로 한다.

**범위가 명시되지 않은 경우 — 레이어 샘플링**:

전체 테스트 파일을 아래 레이어로 분류한 뒤, 각 레이어에서 줄 수 기준 상위 파일을 선택한다.
줄 수가 많을수록 복잡도가 높아 이슈 밀도가 높기 때문이다.
같은 폴더 내 파일이 여러 개이면 최대 2개까지만 고른다.

| 레이어 | 대표 경로 패턴 | 선택 수 |
|--------|--------------|--------|
| 공통 컴포넌트 | `components/`, `ui/` | 최대 3개 |
| 커스텀 훅 | `hooks/` | 최대 2개 |
| 페이지/피처 | `pages/`, `features/`, `app/` | 최대 3개 |
| 유틸/헬퍼 | `utils/`, `lib/`, `helpers/` | 최대 2개 |
| E2E | `e2e/`, `playwright/` | 최대 2개 |

각 레이어에서 최소 1개는 포함한다. 해당 레이어 파일이 없으면 생략한다.

선정된 파일 목록을 검수 시작 전에 한 줄로 출력한다.

---

### Step 3. 검수

선정된 파일을 하나씩 읽고, `@references/review-checklist.md`의 검수 순서대로 평가한다.
각 관점에서 참조 문서의 ❌ 패턴 및 원칙 위반을 확인한다.

---

### Step 4. 결과 출력

아래 구조로 출력한다. 요약이 상단, 파일별 상세가 하단.

---

#### 검수 결과 요약

```
검토 파일: N개 | 🔴 N건 · 🟡 N건 · 🔵 N건

반복 패턴 (2건 이상):
- [패턴명]: N건 — 한 줄 설명
- [패턴명]: N건 — 한 줄 설명
```

문제가 없으면: `검토 파일: N개 | 이슈 없음`

---

#### 파일별 액션 아이템

파일마다 아래 구조로 출력한다. 🔴 → 🟡 → 🔵 순으로 정렬한다.

```
### 파일경로

🔴 L줄번호: 문제. 수정 방향.
🟡 L줄번호: 문제. 수정 방향.
🔵 L줄번호: 문제. 수정 방향.
```

**출력 규칙**:
- 한 줄로 작성한다. 문제와 수정 방향이 명확하면 이유는 생략한다.
- 수정 코드가 짧고 명확하면 인라인으로 제시한다.
- 같은 패턴이 파일 내 반복되면 첫 번째만 표시하고 "(동일 패턴 N건 추가)"로 요약한다.
- 테스트 유형 자체가 잘못된 경우 `@.claude/rules/test-selection.md` 기준으로 적합한 유형을 제안한다.
- 이슈 없는 파일은 `이슈 없음`으로 한 줄 표시한다.

**심각도 기준**:
- `🔴` 테스트 신뢰도를 크게 낮추는 패턴 (잘못된 모킹, 구현 기반 테스트 등)
- `🟡` 유지보수 비용을 높이는 패턴 (waitFor 오용, 불필요한 모킹 등)
- `🔵` 가독성/관례 개선 (디스크립션, 쿼리 우선순위 등)
